基于 KuaiRand 的长序列 CTR 建模与曝光去偏

长序列建模与曝光去偏同等重要：用 KuaiRand 真随机曝光统一报告 test_std / test_rand / gap；长序列侧落地 SIM 双通道与特征增强，去偏侧用 RPD / PA-GSU / Bias-Gate 证明检索层去偏优于纯 IPS。

项目背景｜超长行为用不完，有偏 AUC 又会虚高

工业 CTR 面临两件同时成立的事：行为序列可到万级，全历史 attention 算力不可承受；推荐日志又有曝光偏置，只看标准流量 AUC 容易虚高。本项目基于公开集 KuaiRand，用真随机曝光 is_rand 强制报告 test_std / test_rand / gap（越好 = \|gap\| 越小），并划分 Pure（因果协议）与 1K（长历史检索）双赛道；倾向估计使用无泄漏的 cal_rand 切分。

项目目标｜长序列利用率与无偏稳健性并重

目标不是单刷有偏 AUC，而是在同一裁判下同时回答：如何把超长历史用起来（SIM / 双通道 / 特征 / scaling），以及如何避免「更强匹配更贴热门」（损失去偏对照 → 检索层去偏）。两条线同等重要，互相支撑。

技术路径｜双通道长序列 + Debias-in-Retrieval

长序列建模。 落地 SIM 两阶段 GSU+ESU：硬匹配 tag/author 与软余弦检索把窗长压缩到 top-k，再 DIN 精算。提出 recent⊕semantic 双通道——近因保底、检索补长尾。对照 TWIN 式检索-打分一致性，以及 OneTrans / RankMixer / HyFormer 紧凑 scaling。特征侧迁移 SIGKDD 风格 dense EMA、match、gated tail residual、pairwise rank loss 与 tail aux 等，作为特征工程能力与结构线对照。

曝光去偏。 Pure 与强 dual 骨干上系统对照 IPS/SNIPS/RandCal，发现损失重加权几乎拉不开。据此提出 Debias-in-Retrieval：用自定义 RPD（检索流行度相对窗口 / 随机曝光的 KL）诊断 GSU 选择是否跟随偏热窗口；在检索层做 PA-GSU（分层配额 / 稀有度加分），在融合层做 Bias-Gate（目标流行度桶 ⊕ 17 维检索元特征门控两路兴趣）。

RPD 的核心量可写为：

$$ \mathrm{RPD}_{win}=\mathrm{KL}(P_{ret}\|P_{win}),\quad \mathrm{RPD}_{rand}=\mathrm{KL}(P_{ret}\|P_{rand}) $$

项目结果｜能力锚点与去偏同协议冠军

长序列侧：1K 双通道 sim_1k_dual_multi 取得 rand 0.721、gap −0.034（3 epoch），为历史无偏联合最优锚点；SIGKDD 特征线抬 val，但 gap −0.054，说明结构用长历史优于只堆特征。去偏侧：通宵同协议（1K@1 ep）下 gate_q50 取得最佳 \|gap\| −0.036；gate_meta / soft rare 绝对 AUC 更高但 gap 不收——提分件 ≠ 对齐件。

诚实边界： 公开数据离线实验，无线上 A/B；Pure 与 1K 绝对值不横比；通宵 1-ep 冠军未超过 3-ep 双通道锚点；Pure 短序列上检索干预空间有限；未跑全因子 gate_q50_meta 等交叉。
